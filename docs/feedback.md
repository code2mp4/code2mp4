# Feedback

[简体中文](#简体中文) · [Open an issue](https://github.com/code2mp4/code2mp4/issues/new/choose)

## Product problems

Use the product bug form and include the exact desktop version, operating system, processor architecture, expected behavior, actual behavior, and a minimal reproduction.

Use a small synthetic example when the original project is private. Review logs and screenshots before sharing them. Leave out credentials, account tokens, private media, and personal information.

If you are using the early source from the historical branch, select “Historical open-source prototype” in the form so that the report is not mistaken for a current desktop problem.

## Ideas and documentation

Use the feature request form to explain the creative task and the result you need. Documentation fixes can be submitted as pull requests; see [Contributing](../CONTRIBUTING.md).

## Security

Follow the [security policy](../SECURITY.md). Do not disclose vulnerability details or sensitive project content in a public issue.

## 简体中文

通过[问题表单](https://github.com/code2mp4/code2mp4/issues/new/choose)反馈，并注明桌面版本、系统、芯片、预期与实际表现和最小复现步骤。若使用历史原型，请在表单中选择历史版本。

私有工程尽量换成可分享的合成样例。提交前检查日志和截图，去除密钥、账号令牌、私人素材及个人信息。功能建议请说明具体创作任务与想实现的结果；文档修订可以提交 PR。

安全问题按[安全反馈说明](../SECURITY.md)处理，避免公开披露漏洞细节。
